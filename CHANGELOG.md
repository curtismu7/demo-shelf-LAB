# Changelog

## Unreleased

- Running demos are listed first on the shelf, ahead of the stopped ones; the plan order holds inside each group, and it applies under every filter and What's new.
- A refused Start, Stop or Deploy now shows its reason on the card that was pressed (role=alert), until that card's next action: the agent's own words for the running limit ("13 demos are running and the limit is 10..."), the network-pool fix and compose errors, and the plain-words reason for the token, agent-down and OrbStack-context refusals. The buttons no longer look dead when the agent says no.
- The summary row shows the running count against the limit (`13 running · limit 10`). The count and limit come from the start agent's new read-only `GET /v1/running` (the same count Start checks); an agent started before this change has no such route, so the shelf shows just the limit it knows (`Limit 10 running`) until the agent is restarted. `docker-compose.yml` passes `SHELF_MAX_RUNNING` to the container so that fallback matches the agent.
- jev-lab, obo-lab, jit-lab, agent-preferences-lab and diagram-prove-lab point at their current `-LAB` repos (the old URLs only redirected), so Repo and Copy clone command go straight there, and their `addedAt` is the repo's creation date like every other entry with a repo.
- `addedAt` in the seed is now each repo's GitHub creation date, so apps that were only moved into the seed (muse, ciba-hitl-lab, agentcore-pingone-demo-lab, meridian-a2a-hop, gateway-suite-lab) no longer show as new. Entries with no repo, or a repo URL that redirects to a renamed repo, keep the git-history date. A date-only `addedAt` may be up to 14 hours ahead of UTC. The vendored `scripts/shelf-register.mjs` stamps `addedAt` when it adds an entry.
- The status summary bucket for demos that are not on this machine is now called **Not deployed** (was New), so New means only the recently-added badge.
- What's new: a chip beside the Where filter shows how many demos were added in the last 48 hours (`What's new · 3`) and narrows the shelf to them; their cards and Details carry a New badge. The window is rolling and computed by the server (`isNew` per demo and `newWindowHours: 48` in `/api/shelf`), so every view agrees. It is hidden when nothing is new. New optional registry field `addedAt` (date or ISO timestamp, a real date, not in the future); every seed entry was backfilled from the commit that first put it on `main`.
- customer-agent-lab is registered at port 5603, the port its Docker compose publishes (5600 is the host-run port). The shelf was probing 5600, so a running container showed as Down.
- The running limit never stops ai-guard-sidecar to make room. It still counts toward the limit, but when Start has to stop the oldest demo it skips it; Stop and Stop all still stop it. If every other running demo is one of these, Start is refused (`no-demo-to-stop`) instead of stopping anything.
- Ping products tags: 12 apps that name a Ping product in `pingProducts` (PingOne, PingFederate, PingGateway, the Privilege agent gateway) now carry the matching tag, 16 tags in all, so the Ping products dropdown finds them. Five apps that lived only in a local file are in the committed seed: ciba-hitl-lab, muse (D21; its compose path was wrong), agentcore-pingone-demo-lab (D114), meridian-a2a-hop (D110) and gateway-suite-lab (D118), 75 apps in all. Meridian is tagged simulated and real, Muse simulated, as their READMEs say. demo-field-guide, field-notes-lab and the shelf itself are product-neutral and stay without a product tag.
- Start and Stop from the container no longer report `internal` after the demo actually started. The shelf container mounts `.data` read-only, so its own write to `last-running.json` failed after every successful Start; the start agent already records it, so the shelf now leaves it to the agent (and Deploy through the agent now records too). The note that names a demo stopped by the running limit comes through again.
- At most 10 demos run at once (`SHELF_MAX_RUNNING` changes it). Starting an 11th stops the oldest-started one first and the note says which ("Stopped X (the oldest) to stay within 10 running."). If more than 10 are already running (started by hand), Start is refused and says how many are running; the shelf never stops several at once. Deploy all halts when the limit is reached. A demo started outside the shelf counts as the oldest. The shelf itself is never stopped. It applies from the start agent and the host-run shelf; Restore last set already capped at 10.
- The Docker network guard reads the daemon's real address pools instead of assuming 28. A machine with a custom pool (OrbStack here: 10.200.0.0/16 in /24s = 256 networks) was refused at 28; stock Docker still gets 28. A refused Start now shows the server's explanation, not the raw error code.
- After Start returns, the card keeps its spinner and shows Starting (not Down) while the demo comes up. The shelf looks again every 2.5 s and flips the card to Ready as soon as the health check answers. If nothing answers within 2 minutes, the spinner stops and the card says it started but is not answering, and points to the container logs. Stop clears the state.
- A Help button in the header opens a side drawer listing every way to start a demo: Start on a card, Restore last set after a restart, the `scripts/setup.sh` commands (`--start`, `--start-top`, `--start-all`, with a RAM warning), and fixes when Start does nothing. Escape or Close shuts it; opening a demo's details closes it.
- The seed registers mcp-tools (D3, MCP inspector), mcp-scanner (D4, the same app on port 4810) and mcp-resource-server (D0, port 8081), 52 demos in all. All three carry `mcp-server-built`; the tag's tooltip no longer says "not a tester or inspector".
- New tag `mcp-server-built` ("MCP tool we built") in a new "What we built" group, on hostile-mcp and mcp-surface-lab. The tag filter shows it like any other chip.
- `alsoCatalogIds` on a demo: extra catalog rows the one card covers (they stop showing as planned, and search finds the card by them). The server warns, and `npm run doctor` fails, on an id that is not a catalog row, repeats the entry's own `catalogId`, or is claimed by another demo.
- The seed lists pingone-signin-LAB under A11, covering A4 and A5.
- The seed now registers every standalone app that has a repo and a shelf entry (31 more; 39 in all with pingone-signin-LAB) instead of showing them as Planned. Compose paths are relative to the demo root, so they show as Not installed until cloned there. Two repos claim the same port: ai-gateway-client and session-lab (6880), hostile-a2a and mcp-auth-conformance-lab (4901).
- Planned cards now come only from standalone apps (a repo with a shelf entry) and accepted proposals: 42 instead of 133. The rest of the plan's survey ideas, which no standalone covers, are gone from `data/catalog.json` (the plan itself is untouched). New rows: A28-A30, C40, D54, D100-D109. G4 (mock-authorize) is active again because its repo exists.
- The page opens filtered to Ready. Press the Ready chip (or pick All statuses) to see everything.
- Seed paths follow the repo-home rule: each `composeFile` folder is the repo name (`<name>-LAB`, 21 fixed) and every entry carries its `repo` URL (30 added), so Copy clone command works for all of them.
- The two port clashes are gone: hostile-a2a moved to 4750 (was 4901, held by mcp-auth-conformance-LAB) and session-lab to 6890 (was 6880, held by ai-gateway-client-LAB). `docs/ports.md` is generated from the committed seed only, so it no longer lists apps from a local registry file.

## 1.0.0

- A Start button that cannot be pressed (not installed, no compose file) is drawn muted, not red, so it no longer looks clickable.

- Each installed card says whether the demo is running, installed but stopped, or not installed. The start agent checks for the registered compose file and whether its images are built (read-only `GET /v1/installs`; host-run the shelf does the same itself). "Not installed" greys out Start and shows a tag; with the new optional `repo` field it also offers Copy clone command. "Installed, not built yet" is normal before the first Start, which builds the images. If the check cannot tell (agent not running, Docker slow or not OrbStack), the card behaves as before. The seed entries carry their `repo`. Refresh re-checks the install state (so clone, then Refresh, works at once).

- Removed the unused `SHELF_ONLINE_ONLY` switch (hosted copies only); it had no setting in this repo. `npm test -w server` now allows 30 s per test, so it passes on a busy machine.

- Hovering (or tabbing into) a card lights it up in its kind colour: ring and glow in the spine colour (red Demo, blue Tester, grey Tool), a thicker spine and a faint tint. The colour change also applies with reduced motion; only the lift is motion.

- Every installed card shows Start and Stop side by side (the one that does not apply is disabled, with a tooltip). Stop stops only that demo. Start and Stop refuse an entry that is the shelf's own compose project (`is-the-shelf`), so a Stop can never take the shelf down.

- `npm run agent` starts the start agent and then runs `npm run docker`, which opens the shelf in your browser once it answers. `SHELF_AUTOSTART=0` and `SHELF_OPEN=0` turn these off; both are skipped under `CI`.

- First release as Demo Shelf LAB: a clean-history copy of the internal shelf, restyled to the shared LAB UI standard (shelves, boxes, status lights, Auto / Light / Dark picker), registered demos on the first shelf and planned ideas below, tag filters behind a toggle.
- The seed lists the -LAB apps. No host is allowed beyond loopback unless `SHELF_ALLOWED_HOSTS` names it.
- `GET /api/health` (`demo-health/1`) for the shelf itself.
- Docker always: the shelf runs in a non-root, read-only container with no Docker socket (`npm run docker`) and Start / Stop is always on, with no off switch. A host-side start agent (`npm run agent`, loopback, bearer token) runs `docker compose` for registered demos; the container probes demos through `host.docker.internal` with their own Host header. One Start or Stop button per card, by state.
